# 熱烈電卓町中華

Unity Entitiesで動く、料理名を入力して共有食材を一気に料理する3D得点対戦プロトタイプ。

## 更新内容（お客さんの食事）

- 配膳から10秒以上経った完成料理を、約2.5〜4.5秒間隔でランダムに1皿選んで食べる。食べた人数分だけ皿と共有在庫が減る。
- 食べた人数×料理の基本点を、その皿を最後に作ったプレイヤーへ追加する。調理履歴には食事による人数と得点も記録する。
- 食べられた料理の3Dモデルを60〜96個、皿から画面の端まで噴き上げて降らせる。食事の感想は「美味しい！」「うまい！」「ごちそうさま！」「おかわり！」など18種類から毎回1つだけ大きく表示し、全画面の光・紙吹雪、得点札へ飛ぶ加点、効果音を重ねる。連続して同じ言葉は出さない。
- 960×600のWebGL表示でカウントダウン文字が切れないよう、文字の描画領域を広げる。

## 更新内容（素材の増量と円卓外への広がり）

- 「3、2、1、料理開始！」の3秒間に初期食材10,000個を段階的に降らせる。試合の120秒とCPUは掛け声の後に動き始める。追加で降る素材の総数上限はなく、調理しなければ1秒あたり約65個ずつ増える。
- 開始演出の食材は高さ10〜17から降る。試合中の追加食材は高さ8〜11.5から落下する。
- 食材モデルは従来の拡大サイズを維持。円卓と回転台を実寸で約2.6倍にし、皿と盛り付けも卓に合わせて拡大する。
- 約70％の食材を円卓上に、残りを円卓の外側に降らせる。調理で弾かれた素材も円卓の外へ飛び出す。
- 回転台に近い卓上素材ほど速く周回する。円卓の外に落ちた素材は床に留まり、調理時に弾かれた素材は一時的に軌道を外れる。
- 在庫10,000個をすべて3D描画する。食材同士の重なりは許し、中央の完成料理は上から見えるようにする。
- 金色の食材は床や球状の境界で反発係数0.98相当で跳ね、横方向の速度も保つ。見た目、影、当たり判定は同じECS位置を使う。
- 金素材は開始時0個。追加の食材からランダムに平均約10秒に1個出現し、大きさは通常食材の3倍。使用した金素材1個につき、その料理1人前の基本点を2回分追加する。大型の金素材に当たった食材は周囲へ跳ねる。
- 初期食材の約70％を半径20の円卓上、残りを半径37までの円卓外に散らす。弾かれた食材は画面外まで飛び、半径40の球面で反射する。固定カメラは以前の斜め上の画角に戻し、狭い画面や皿が上段に増えたときだけ画角を調整する。
- 料理完成は1〜9、10〜39、40〜119、120人前以上の4段階。上の段階ほど光の輪、星、紙吹雪、得点演出、音を強める。
- 飛行する調理素材が周辺素材を弾く範囲と、マウスで素材を指したときの判定を拡大。

## 更新内容（v0.14：さらにやさしいCPU・モデル1.5倍）

- やさしいCPUは初回25秒後、以後20秒ごとに行動（120秒の試合で最大5回）。原料だけで作れる8候補から、基本得点が最も低い調理を選ぶ。完成料理は材料として使わない。ふつう・むずかしいの挙動は維持。
- すべての食材と完成料理のモデルを従来の1.5倍に拡大。当時の金素材は通常素材の1.28倍。飛行中の素材、不足素材の幻影、配膳中の料理も同じ比率で拡大する。

- この段階では在庫数・レシピ・最大調理数・得点・金素材の出現率を維持。

| CPUレベル | 最初の行動 | 以後の間隔 | 料理の選び方 |
|---|---:|---:|---|

## すぐ遊ぶ（このMac）

作業フォルダ内の `Builds/熱烈電卓町中華.app` を開く（ソースZIPにはビルド済みアプリを含めていない）。初期状態は **シアン＝あなた、オレンジ＝CPU**。
タイトルで「いただきます！」またはEnterを押すと120秒の試合が始まる。まず `chahan` または `チャーハン` を入力してEnter。
相手が作ったカレーを見つけたら `currydoria` を試す。

| 操作 | 動作 |
|---|---|
| タイトルで左右キー／レベルをクリック | CPUの強さを選択 |
| 文字入力 → Enter | フィールド全体から、可能な最大数を一括調理 |
| 日本語IMEのEnter | 変換確定。そのあともう一度Enterで調理 |
| F3 | 音楽のON/OFF（効果音は維持） |
| F1 | 発見済みの料理図鑑を開閉。料理名クリックで入力欄へ |
| 図鑑中の左右キー／ホイール | 20件ずつ、全20ページを切替 |
| Esc | 対戦中は入力消去／図鑑を閉じる。リザルトではタイトルへ戻る |
| F5 | 再戦／新しい120秒の試合。発見は保存される |

MacでファンクションキーがOS操作になる場合は `fn` と一緒に押す。
ゲーム画面をクリックしてから、中央の入力欄に料理名を入力する。シアンをプレイヤーが操作し、オレンジは選択した強さのCPUが操作する。

常時画面は得点2つ、残り時間、中央の入力欄1つと、完成料理に追従する料理名タグ。時間切れで専用リザルト画面に移り、勝敗と確定得点を表示する。
不足素材は0.8秒の半透明3Dモデル。未登録の料理名は入力欄の淡い反応音・光だけで返す。

## unityroom向けWebGL版

Unity 6000.3.13f1の **Web Build Support** を入れ、プロジェクトのルートで以下を実行する。

```sh
"/Applications/Unity/Hub/Editor/6000.3.13f1/Unity.app/Contents/MacOS/Unity" \
  -batchmode -nographics -quit -projectPath "$PWD" \
  -executeMethod SpinningFeast.Editor.ProjectTools.BuildUnityroomWeb \
  -logFile /tmp/spinning-feast-webgl-build.log
```

出力は `Builds/unityroom-web/`。Development Buildを無効、圧縮をGzip、Decompression Fallbackを無効に設定する。`Build/` 内の4ファイルをunityroomの「WebGLアップロード」に登録する。フォルダ一括アップロードを使う場合は展開した `Build/` フォルダをドラッグ＆ドロップする。`index.html` と `TemplateData/` はローカル確認用に同梱している。

ローカルでは `index.html` を直接開かず、圧縮ファイルに `Content-Encoding: gzip` を付けるHTTPサーバーから起動する。

### WebGL版の日本語入力

Unity Webの組み込みIMEは非対応のため、対戦中はブラウザの入力欄で変換を受け取り、入力内容をUnityに渡す。入力処理は `Assets/Plugins/WebGL/FeastWebInput.jslib` からビルドの `.framework.js` に組み込まれる。unityroomには通常どおり `Build/` の4ファイルをアップロードする。[UnityのIME対応状況](https://docs.unity.com/en-us/engine/6000.0/manual/input/imeinput)

公開前に、ローカルのWebGLビルドとunityroomのプレビューで以下を確認する。

- 日本語IMEで「ちゃーはん」と入力し、「チャーハン」に変換する。最初のEnterで変換を確定し、次のEnterで1回だけ調理する。
- 変換中にEscで変換を取り消せることと、変換していないときはEscで入力欄を消去できることを確認する。
- `chahan` の英字入力、料理名の貼り付け、F1での図鑑の開閉、F3での音楽切替、F5での再戦を試す。
- Chrome、Firefox、Safariで、埋め込み表示・別タブ・全画面で入力欄の位置とフォーカスを確認する。

## 収録レシピ（試したいときの参考）

全400種類は [レシピ一覧](Docs/RecipeCatalogue.md) を参照。以下は既存10種の早見表。未発見でも入力可能。図鑑には成功した名前だけが現れる。括弧内は英字入力の例。

| 料理 | 1人前の材料 | 点数 |
|---|---|---:|
| チャーハン (`chahan`) | 米2・卵1・にんじん／玉ねぎ1 | 100 |
| カレー (`curry`) | 米2・豚／鶏／豆腐1・にんじん／玉ねぎ／トマト1・香辛料1 | 120 |
| チキンライス (`chickenrice`) | 米2・鶏1・トマト1 | 110 |
| 餃子 (`gyoza`) | 小麦粉1・豚／鶏／豆腐1・玉ねぎ／にんじん1 | 100 |
| 麻婆豆腐 (`mapo`) | 豆腐2・豚／鶏1・香辛料1 | 130 |
| 酢豚 (`subuta`) | 豚2・トマト1・玉ねぎ／にんじん1 | 120 |
| オムライス (`omurice`) | チキンライス／チャーハン1・卵2 | 180 |
| カレードリア (`currydoria`) | カレー1・チーズ1 | 180 |
| チーズカレードリア (`cheesecurrydoria`) | カレードリア1・チーズ2 | 240 |
| 天津飯 (`tenshinhan`) | チャーハン1・卵1・香辛料1 | 190 |

「／」は代用可能。余った食材は消費しない。調理数は任意の上限で打ち切らない。
完成品を次の料理にすると、次の料理の点数を調理者に加点する。前の調理者の得点は失われない。
料理グラフは循環させていないので、同じ料理を往復する無限得点ループは発生しない。

## 実装の場所

- `Assets/SpinningFeast/Core/FeastCpu.cs`：3段階の思考間隔と料理選択。
- `Assets/SpinningFeast/Core/Recipes.cs`：レシピ型と、使用材料だけの小さな最大流グラフによる最大調理数。
- `Assets/SpinningFeast/Core/Catalogue.cs`：生成された35食材・400レシピ、入力名の正規化。
- `Assets/SpinningFeast/Rendering/FeastExpansionMeshes.cs`：追加食材24種と、16系統の盛り付け・具材表現。
- `Assets/SpinningFeast/Runtime/FeastSimulation.cs`：ECS状態、順序付きコマンド、素材消費、配膳、落下・飛翔ジョブ。
- `Assets/SpinningFeast/Runtime/FeastApp.cs`：キーボード／IME、CPUレベル選択、得点・図鑑。
- `Assets/SpinningFeast/Runtime/FeastSound.cs`：効果音の重なり・音量・左右定位、音楽の同期と終盤パート。
- `Assets/SpinningFeast/Rendering/FeastEffects.cs`：世界内の粒子、波紋、連鎖、発見、大皿と提灯の反応。
- `Assets/SpinningFeast/Rendering/FeastHudEffects.cs`：入力・得点・タイマー・タイトル／リザルトの一時演出。
- `Assets/SpinningFeast/Runtime/FeastPresentationProbe.cs`：任意起動の120秒対戦・演出寿命・再戦の検査。
- `Assets/SpinningFeast/Rendering/FeastMeals.cs`：写真を参考にしたカレー・麻婆豆腐の造形。
- `Tools/generate_audio.py`：外部ライブラリ不要の効果音・音楽生成。
- `Assets/SpinningFeast/Rendering/FeastView.cs`：固定カメラ、回転台、GPUインスタンス描画、大皿。
- `Assets/SpinningFeast/Rendering/FeastMeshes.cs`：ローポリ食材メッシュ。
- `Assets/SpinningFeast/Editor/ProjectTools.cs`：ECS検証、シーン生成、Macビルド。
- `Docs/ImplementationPlan.md`：設計判断、段階計画、既知の制約。
- `Docs/Validation.md`：検証結果と再実行方法。

初期食材10,000個、補充65個/秒。素材の総数上限は設けない。食材同士の剛体衝突は使わず、床への落下と簡易反発を並列計算する。

描画は **Built-in Render Pipeline + Graphics.RenderMeshInstanced**。Entities Graphics / Unity Physics / Netcodeは導入していない。
ゲームの正本はEntity、表示と日本語入力はMonoBehaviourのハイブリッド構成。
